# 플랜별 클립 추가 저장 한도

관련 이슈: #150. Free는 폴더당 50개, Pro는 300개까지 생성·개별 복구로 클립 수를 늘릴 수 있다. 기존 초과 데이터는 삭제하거나 일부만 잠그지 않는다.

## 구현 범위

이 변경은 클립 생성·휴지통 복구의 한도 검사와 필요한 복구·영구 삭제 경쟁 보호를 구현한다. Free의 단일 폴더 열람·편집 제한도 적용한다. 선정·생성·복구와 관리 예외는 [폴더 접근 문서](free-folder-access.md)를 따른다. 별도 태그 유료화는 포함하지 않는다. 현재 허용된 폴더의 기존 콘텐츠 수정·삭제는 개수 때문에 차단하지 않는다.

## 유효 플랜과 원자적 검사

- `PRO`, `ACTIVE` 또는 `CANCELED`, 미래의 `currentPeriodEnd`를 모두 충족하면 300개다. 그 외에는 50개다. 자동갱신 플래그만으로 만료된 Pro를 인정하지 않으며 해지 후 결제한 잔여 기간은 보장한다.
- 생성·복구는 해당 개인 워크스페이스의 구독 행을 먼저 잠그고 폴더·클립 순으로 검사한다. 여러 폴더·클립을 잠글 때는 ID 순서를 통일한다. 한도용 시각은 잠금을 얻고 최종 검사할 때 정한다.
- 현재 활성 클립 수와 추가 수를 같은 트랜잭션에서 검사하고 저장한다. 생성·복구가 경합해 마지막 슬롯을 두 번 사용하는 것을 막는다. 결제 성공·해지 등 구독 쓰기도 같은 구독 행 잠금과 직렬화된다.
- 구독 행이 누락된 기존 개인 워크스페이스는 기본 Free 구독을 생성해 같은 잠금 경계에 참여시킨다. 이는 결제 결과 대사를 대신하지 않는다.

## 복구와 초과 데이터

개별 삭제 클립을 복구할 때는 폴더별 현재 미삭제 클립 수에 복구할 고유 클립 수를 더해 검사한다. 여러 폴더 중 하나라도 실패하면 전체 복구를 롤백한다. 최종 쓰기 전에 소유권·삭제 상태·부모 폴더를 다시 검증한다.

폴더 자체의 복구는 기존 내용을 되돌리는 예외다. Free의 200개 폴더나 Pro의 350개 폴더도 기존 내용 그대로 복원할 수 있지만, 추가 개별 복구로 201개·351개를 만드는 요청은 거부한다. Free에서는 선택된 폴더의 복구만 허용하며, 기존 클립 수 초과 예외가 다른 폴더의 접근 잠금을 면제하지는 않는다.

## 오류 응답

클립 한도 초과는 `409`로 반환하며 기존 오류 필드에 `code`, `details`를 추가한다.

```json
{
  "statusCode": 409,
  "message": "폴더의 클립 추가 저장 한도(50개)를 초과합니다.",
  "error": "Conflict",
  "code": "CLIP_LIMIT_EXCEEDED",
  "details": {
    "resource": "clips",
    "folderId": "folder-id",
    "limit": 50,
    "currentCount": 50,
    "requestedIncrease": 1,
    "upgradeCanResolve": true
  }
}
```

`upgradeCanResolve`는 Free에서 해당 요청이 Pro 한도 안에 들어오는 경우에만 참이다. 복구 요청 중 한 폴더라도 추가 후 300개를 넘으면 업그레이드로 해결 가능하다고 안내하지 않는다. 이 필드는 한도에 대한 안내이며 다른 권한·삭제 조건을 면제하지 않는다.

## 이미지 정리와 배포

이미지 업로드 뒤 최종 생성이 한도 초과 등으로 실패하면 생성과 같은 구독 잠금을 얻은 후 업로드 URL의 DB 참조를 확인한다. 커밋 응답 유실로 이미지가 이미 저장된 경우 보존하고, 미참조가 확인된 경우만 삭제한다. 확인·삭제 실패 시 원래 오류를 반환하며 정리 실패를 기록한다. 프로세스 종료·외부 저장소 장애에 대한 영속 정리 큐는 포함하지 않는다.

복구와 영구 삭제·만료 정리가 경합할 때 삭제 대상 상태를 잠금 아래 다시 확인한다. 실제로 삭제한 행의 이미지 URL만 정리 대상으로 반환한다. 복구된 폴더의 콘텐츠를 오래된 삭제 후보 조회값만으로 삭제하지 않는다.

클립 한도 자체에는 스키마 변경이 없지만, 함께 적용하는 폴더 접근 선정에는 `20260908080000_add_free_folder_access` 마이그레이션이 필요하다. 새 환경변수는 없다. 배포 전 Free 50개 초과·Pro 300개 초과 폴더를 집계하고, 요금제 안내를 절대 보관량이 아닌 추가 저장 한도 및 기존 데이터 보존 예외에 맞춘다. 클라이언트는 한도 오류 내용을 표시하며 서버의 최종 검사를 대체하지 않는다.

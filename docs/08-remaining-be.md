## P1 · FE/운영 전환 전에 남은 확인

- [ ] FE에 [변경 계약](09-p1-fe-api-contract.md)을 전달하고 CSRF 헤더, 가격 버전·UUID, 결제 결과 객체를 반영한다. 구 FE 입력은 새 confirm에서 400이므로 전환 순서를 맞춘다.
- [ ] 운영자가 판매 가격과 `CLIP_UPLOAD_REQUESTS_PER_MINUTE`를 결정·설정한다. 가격 미설정 시 공개 조회/신규 청구 거부, 업로드 제한 미설정 시 multipart 503. 예시 설정에는 임의 수치를 넣지 않았다.
- [ ] 추가 마이그레이션 3개를 실제 배포 DB 버전에서 검증·적용하고 구 BE의 최초 결제 트래픽을 배제한 뒤 전환한다. 기존 데이터 삭제/금액 변경/과거 유실 결제 백필은 없다.
- [ ] 보호된 배치 API 스케줄 실행, 장기 PENDING 주문의 운영 대사 절차를 확인한다. 결제사 조회 불가/주문 없음/빌링키 저장 전 장애는 자동 재청구하지 않고 확인 대상으로 유지한다.
- [ ] 실제 nginx/CDN 본문 상한·로그, 인증 응답·이미지 접근을 확인한다. 업로드 요청 제한은 프로세스 단위이므로 여러 인스턴스의 공통 한도는 별도 프록시 설정이 필요하다.

## P2 · 다음 구현 작업

- [ ] 휴지통 복구·삭제 사전 조회의 불필요한 전체 본문 읽기 제거. 현재 `findDeletedClipsByIds` 경로에 본문 조회가 남아 있다. 폴더 사전 조회는 이미 메타데이터만 읽는다. 목록·상세 타입과 작업 검증용 메타데이터 타입을 분리하되 상세 응답은 유지한다.

## 검증

- 단위 테스트: 전체 55개 suite, 289개 통과.
- E2E: 최종 전체 실행 9개 suite, 109개 통과. 최초 주문번호의 토스 길이 제약과 쿠키·업로드·DB 동시성·복구를 검증했다.
- DB: `/tmp`의 격리된 PostgreSQL 16.15 `test_db`에 전체 32개 마이그레이션 적용 성공. 실제 앱 DB·운영 DB는 사용하지 않았다. 저장소 Docker 구성은 PostgreSQL 18이므로 배포 버전 검증은 위 항목으로 남긴다.
- 제품 빌드(`pnpm build`), 테스트 포함 전체 TypeScript 검사(`tsc --noEmit --incremental false`), ESLint 통과. 전체 ESLint에서 발견한 신규 앱 테스트 타입 오류를 수정하고 영향 파일을 재검증했다.
- 외부 결제/OAuth는 가짜 응답을 사용했다. 실과금·배포·운영 전체 확인은 하지 않았다.

## 운영자 결정 필요 · 임의 확정하지 않음

- 실제 판매 가격, 가격 변경 고지·동의 및 적용 시점, 환불·자동갱신 정책.
- 업로드 요청 허용 횟수와 다중 인스턴스 공통 제한.
- 운영자·개인정보 담당자, 보유·파기 기간, 실제 외부 처리 업체·국가와 연락처.
- 공개 CDN 보관 정책 유지 여부. 비공개 자료 보관으로 바꾸려면 private 객체·인증 URL 전환을 별도 설계한다.

FE 정책 페이지·가격 표시에는 운영자가 확정한 정보만 반영한다. 원 문서가 링크하던 `01`/`03`/`05`/`06`/`07` 문서는 현재 이 BE 작업 트리에 없어, 이번 재확인은 실제 코드·테스트·GitHub 상태를 근거로 했다.

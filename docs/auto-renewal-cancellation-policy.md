# 자동갱신 청구와 해지의 처리 순서

관련 이슈: [#147](https://github.com/gksktl111/easy-clip-be/issues/147). 자동갱신 청구 선점과 해지를 같은 구독 행 잠금에서 처리해, 해지 완료 후 오래된 배치 조회값으로 새 청구를 시작하지 않도록 한다. 성공 결과와 미확정 결제의 복구는 [결제 대사 문서](auto-renewal-payment-reconciliation.md)를 따른다.

## 이번 구현의 기준

청구 시작의 기준은 `PENDING` 주문 선점 트랜잭션의 커밋이다. 선점 후 외부 HTTP 요청을 전송하며, 외부 결제를 기다리는 동안 DB 잠금을 유지하지 않는다. 선점과 해지 중 먼저 확정된 작업에 따라 다음과 같이 처리한다.

| 해지가 확정된 시점        | 이번 청구                                                                         | 다음 자동갱신 |
| ------------------------- | --------------------------------------------------------------------------------- | ------------- |
| 청구 선점 전              | 배치에 이미 조회됐어도 선점 재검사에서 거절한다. 주문 생성·외부 과금 없음         | 중단          |
| 청구 선점 후, 결과 미확정 | 이번 청구가 완료될 수 있다. 성공하면 결제한 기간을 반영하고, 결과 유실은 대사한다 | 중단          |
| 결제 성공 반영 후         | 결제한 이용 기간을 유지한다                                                       | 중단          |

선점 커밋 후 HTTP 전송 전이라도 두 번째 규칙을 적용한다. 선점 직후 프로세스가 종료돼 실제 과금이 없을 수도 있으므로, 미확정 상태를 결제 성공이나 실패로 단정하지 않는다. 해지 API는 이미 시작된 결제를 자동 취소·환불하지 않으며, 환불 기능·정책은 별도 범위다.

## 원자적 검증

- 청구 선점 시 최신 `PRO / ACTIVE`, `autoRenew`, 결제 제공자·빌링키·고객키, 청구 예정일, 기간 종료일을 배치의 후보 스냅샷과 비교한다. 변경됐다면 이번 후보는 건너뛰고 다음 조회에서 최신 상태로 판단한다.
- 같은 구독에 미확정 결제가 있으면 다른 주문번호로도 새 자동갱신을 선점하지 않는다. 해지와 선점은 같은 구독 잠금으로 순서를 정한다.
- 해지는 최신 구독을 검증하고 `autoRenew=false`, `status=CANCELED`, `nextBillingAt=null`을 함께 저장한다. 이용 기간을 줄이거나 미확정 결제 행을 삭제하지 않는다. 아직 유효한 Pro 해지 구독에 대한 반복 해지는 같은 결과를 반환한다.
- 자동결제 성공 반영도 구독 → 결제 순서로 잠그고, 최신 자동갱신 의사를 유지한다. 대사나 지연된 성공 응답이 해지를 취소하지 않는다.
- 재개 API와 빌링 인증의 즉시 과금 없는 재개 경로는 잠금 안에서 최신 상태·키·유효 기간을 검증한다. 다음 결제일은 최신 `currentPeriodEnd`에서 계산한다. 재개 조건이 달라지면 `409`이며 신규 과금으로 전환하지 않는다.
- 유효한 기간이 남은 상태에서 사용자가 명시적으로 재개하면 이후 성공 반영은 그 재개 의사를 따른다. 동시 해지·재개의 순서는 DB에 확정된 순서로 정하며, 클라이언트 요청 발송 시각으로 역순 정렬하지 않는다.
- 기간이 끝났고 이전 자동결제가 미확정이면 빌링 인증의 신규 과금 경로도 `409`로 차단한다. 먼저 이전 결제 결과를 확인해야 한다. 최초 결제와 별도 추가 결제 전반의 동시성·복구는 이번 범위가 아니다.

## 해지 응답과 클라이언트 안내

`PATCH /subscriptions/me`의 `CANCEL` 성공 응답은 기존 필드를 유지하고 `cancellation`을 추가한다. `RESUME` 응답에는 이 필드를 포함하지 않는다.

```json
{
  "plan": "PRO",
  "status": "CANCELED",
  "autoRenew": false,
  "currentPeriodEnd": "2026-09-08T00:00:00.000Z",
  "nextBillingAt": null,
  "provider": "TOSS_PAYMENTS",
  "cancellation": {
    "pendingRenewalPayment": true,
    "message": "자동갱신이 해지되었습니다. 이미 시작된 결제는 완료될 수 있으며, 결제된 이용 기간은 보장됩니다."
  }
}
```

- `pendingRenewalPayment=true`이면 이번 결제가 완료될 수 있음을 해지 완료 화면에 안내한다. 결과가 아직 확정되지 않았으므로 응답의 이용 기간은 이후 대사로 연장될 수 있다.
- `false`이면 미확정 주문이 없다는 의미다. 과거에 과금이 없었다거나 환불됐다는 뜻은 아니다.
- 이 값은 해지 트랜잭션 시점의 스냅샷이다. 안내 문구를 과금 결과의 증빙으로 사용하지 않는다. 응답 직후 결제 결과가 확정될 수 있다.
- `GET /subscriptions/me`의 응답 계약은 유지한다. 클라이언트는 해지 응답의 안내를 표시하고 이후 구독 조회로 최신 이용 기간을 갱신한다.

스키마 변경과 새 환경변수는 없다. 실제 결제를 취소하는 외부 API 호출도 추가하지 않는다.

## 검증 기준

- 배치 대상 조회 뒤 해지가 먼저 완료되면 외부 호출과 주문 생성이 없는지 확인한다.
- 결제 응답을 명시적으로 지연시킨 상태에서 별도 DB 연결의 해지가 끝나는지, 지연된 성공과 대사 이후에도 다음 청구가 중단되는지 확인한다.
- 성공 반영 후 해지는 새 이용 기간을 보존하는지 확인한다.
- 오래된 기간을 읽은 두 재개 경로가 최신 기간을 기준으로 다음 결제일을 설정하는지 확인한다.
- 변경된 결제 키·청구일, 다른 번호의 미확정 주문이 있는 경우 선점이 거절되는지 확인한다.
- 기간 만료 후 미확정 주문이 있는 빌링 인증은 추가 과금 없이 거절하는지 확인한다.
